# 21 会话、留存与观察窗口

## 会话不是浏览器标签页

项目按source/app/anonymous_id的活动序列切会话，相邻事件间隔达到30分钟开始新会话；跨午夜不强行拆开。会话按开始时的香港日期归属。截止时最后一次活动尚未静默满30分钟，会话标为未关闭，不把它当已经结束的完整时长样本。

```text
23:50活动 → 次日00:10活动（间隔20分钟，同一会话）
次日00:40活动（间隔恰好30分钟，新会话）
```

会话日汇总里的users是“当日开始会话的去重参与者”，不是轻量当日所有活动UV。有人只在前一天开始的跨午夜会话中继续活动，会影响后一日UV，却不一定成为后一日新会话用户。

## D1/D7怎么手算

cohort是同一首次观察日期的一组应用内匿名标识。D1看其第二个日历日是否回访；D7看第七天后对应日是否回访，不是期间任意一天回访。假设1月1日首次观察A、B、C；1月2日A、C回来，D1=2/3。1月8日只有B回来，D7=1/3。

观察日期尚未结束时不能提前给出完整留存率。项目为尚未成熟的D1/D7保存eligible=0、retained=null，而不是0%。在真实有限保留窗口中，还要检查coverage：丢失数据导致的不完整，不等同于没有回访。

## SQL思路

先按应用/标识/业务日期去重，得到用户活动日；再求**完整且仍在保留期内的观察状态**中的 MIN(date) 作为 cohort；Join到cohort+1或+7的活动日。这是“本项目保留观察窗口内首次看到”，不是用户一生第一次访问。不要把“最近7天原始文件”直接当作全部观察历史。

```text
事件 → 每用户活动日去重 → 首次观察cohort
                               ↓
                       D1/D7观察日期是否可用
                               ↓
                       分子/分母/成熟与缺口状态
```

## 操作与验收

本章有两条实现路径，需要先辨认。`behavior.py` 是固定合成输入的教学基准，输出 `first_observed_in_input`；`real_behavior.py` 是真实作业共享的覆盖/辅助状态契约，小样本 oracle 供测试使用，实际分布式处理由 `warehouse/spark/real_behavior.py` 执行。只跑 Python 测试不能写成“真实 Spark 留存任务已完成”。

```text
原始7天事件 + 仍有效的最多30天最小辅助状态
     → 按app和匿名标识形成活动日/首次观察日
     → 检查来源代际、原始到期时间、覆盖清单和截止时间
     → 未成熟 pending / 覆盖不足 incomplete / 可算 complete_accepted_prefix
     → 只有可算状态才提供有效分母和留存人数
```

| 情形 | 状态与分母 | 正确的解释 |
|---|---|---|
| 9月5日队列的D7观察日为9月12日，但该日尚未结束 | pending；eligible=0，retained=null | 还没有等到完整观察日 |
| 观察日已结束，但保留窗口起点晚于cohort日，或登记了覆盖缺口 | incomplete；eligible=0，retained=null | 无法证明历史完整，不能按0%发布 |
| 观察期成熟、所需辅助历史有效且覆盖清单通过 | complete_accepted_prefix；eligible=队列人数 | 仅对已接受的连续事件范围算留存，不保证所有真实访问都被采集 |

举例：合成标识A在9月5日首次出现，9月12日回来。9月5日原始负载到期后，合法辅助状态仍保存必要的首次观察与活动信息，可把A保留在9月5日队列；如果只看9月12日原始记录，A会被错误划成9月12日“新用户”。辅助状态到30天也须到期，复制文件或重放不能把它变成永久身份历史。

当前实现先判断成熟期，再判断覆盖；真实缺口检查在所登记的cohort至截止范围内采取保守判断。遇到 pending 不意味着系统已经证明没有缺口。实际展示应保留覆盖元数据，不能只看一个百分比。参见下面两个测试文件中的边界样例。

```powershell
# Windows PowerShell；前置：第11章依赖已安装；仅运行合成测试，不启动VM
Set-Location -LiteralPath (git rev-parse --show-toplevel)
& .\.venv\Scripts\python.exe -m pytest -q tests/test_behavior.py tests/test_real_behavior.py
Get-Content src/snow_statistics/real_behavior.py
```

预期命令退出码为0，测试包含旧观察跨越原始窗口、缺口与未成熟不转成零、复制不续期、数据源代际不混合，以及跨午夜、恰好30分钟等边界。报错首先按测试名定位是哪一类契约，不通过时不要通过删除coverage检查来取得留存率。

## 练习与答案

题：9月13日首次观察的用户，在9月14日上午已有一次访问，此时能发布完整D1留存吗？答案：观察日期尚未结束，不能按完整D1批次给出最终值。可以内部查看进行中的信号，但正式成熟期口径保持未成熟；若数据读取有缺口，还要另外标明coverage不完整。

排错从应用ID、时区、去重日期、cohort输入范围、观察期成熟和coverage开始，不优先修改百分比小数位。
