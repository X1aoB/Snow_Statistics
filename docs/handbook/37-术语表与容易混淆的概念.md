# 37 术语表与容易混淆的概念

## 按一条数据的旅程记忆

```text
事件 → 契约校验 → 持久化确认 → 去重聚合 → 私有增量同步
→ ODS原始 → DWD事实/DIM维度 → DWS汇总 → ADS应用 → 版本化发布
```

术语应能对应项目中的具体对象，而不只是背英文全称。本表用项目语境解释；同一个词在其他系统里可能有不同粒度。

## 业务与指标

| 术语 | 本项目里的含义 | 易错点 |
|---|---|---|
| PV | 通过校验去重后的页面浏览事件数 | 所有HTTP请求数不等于PV |
| UV | 按应用、日期、有效匿名标识去重 | 不是认证自然人数，每日UV不能直接求区间UV |
| session | 同应用匿名标识30分钟无活动形成边界的行为组 | 跨午夜不必拆分；前端session ID不是离线唯一依据 |
| cohort | 按规定首次观察日期进入的用户群 | 有限保留窗口不代表终生首次 |
| retention | 具备完整观察资格的队列在目标日仍活动的比例 | 未成熟分母和缺口不能算成0 |
| funnel | 按时序及关联键约束的一组转化步骤 | 单独各事件数量不能直接拼成同一批人的漏斗 |
| attribution | 把一次成功分配给符合规则的入口 | 最近有效入口、30分钟、每点击最多一次 |
| SCD2 | 维度变化保留有效区间历史 | 直接覆盖旧分类会改写历史解释 |
| 累积快照 | 一行随着流程补充多个里程碑 | 工单重开需分别定义轮次 |
| 周期快照 | 在每天等固定时点记录状态 | 当天无事件不代表快照没有意义 |

## 身份与数据边界

| 术语 | 本项目里的含义 | 易错点 |
|---|---|---|
| event_id | 一条统计事件的重放身份 | 不替代request_id业务去重 |
| request_id | 一次业务请求的关联身份 | 不公开，不把详细错误放进事件 |
| anonymous_id | 单应用浏览器统计标识 | 去标识不等于绝对匿名 |
| jump_id | 一次入口跳转标记 | 不跨站传用户ID，不补录同意前的到达 |
| source | real或synthetic入口来源 | 不能只在看板加标签而底层混存 |
| seq/offset | 某个源或分区的单调位置 | 换collector代际或分区后不能盲目比较 |
| cutoff | 结果纳入数据的固定截止时间 | 与作业开始时间、业务日期不同 |
| coverage | 哪些窗口完整观察的证据 | 文件存在/最大事件时间不等于完整观察 |
| quarantine | 被规则隔离的非法或冲突数据 | 不可默默丢弃并报告零异常 |

## 引擎与存储

| 术语 | 用途 | 在项目中的边界 |
|---|---|---|
| SQLite WAL | 轻量事务库的预写日志模式 | 写并发仍有限，主文件外有WAL空间 |
| Kafka | 持久消息分区、缓冲与重放 | 日常单节点，专题三节点KRaft |
| Debezium CDC | 读取数据库提交变更 | 需理解snapshot/binlog和删除语义 |
| HDFS | 分布式文件块与副本 | NameNode管元数据，DataNode存块 |
| YARN | 分配计算容器和调度资源 | 不等于Spark计算逻辑 |
| Hive | 表元数据与SQL生态 | 本项目Spark利用元数据，不能把存储全叫Hive数据库 |
| Spark | 离线批处理与SQL计算 | action触发执行，shuffle/分区影响代价 |
| Flink | 有状态流处理 | Event Time、水位线、Checkpoint分别有职责 |
| Doris | 分析结果查询与发布 | 公开网站不直接访问，不提供任意SQL |
| Iceberg | 表元数据、快照和演进 | 位于Parquet等数据文件之上 |
| Airflow | 任务依赖、重试和运行记录 | 不管理VMware开关，不替代引擎 |
| OpenLineage | 作业和数据集血缘事件规范 | 协议不自动发现全部依赖 |
| Marquez | 保存/查询OpenLineage记录 | 可停用，不阻断业务和计算 |
| ZooKeeper | 多数派协调、会话、版本控制 | 独立专题，KRaft Kafka不依赖它 |

## 一致性与恢复

幂等表示同一逻辑操作重复执行，最终业务效果保持一致。至少一次表示失败恢复可能重复投递，需要下游处理重复。最多一次通常避免重试带来的重复，但可能丢失。恰好一次必须说明是在状态计算、外部事务还是端到端业务效果这一层，不可把名称当成证明。

Checkpoint是一致的状态与源进度快照，savepoint常用于有计划的状态迁移；二者都不自动恢复外部数据库中所有业务副作用。Doris事务预提交和提交决定外部可见性，稳定业务键还要防止跨尝试重复。

watermark是引擎基于事件时间进展的判断，不是现实世界保证“再也没有旧事件”。allowed lateness或项目迟到修正窗口决定何时还更新实时结果；超晚新数据进入离线校正。backpressure是下游变慢向上游传递压力，不一定是Kafka本身故障。

## 发布与公开保护

pending表示还未到发布时间；公开组的empty表示固定截止范围内没有该组可累计的已记录数据，不能单凭它证明所有真实行为都完整采集或自然业务量为零。suppressed表示已有记录但未达到公开规则，published才携带可展示计数。stale是汇总生成状态过期，unavailable是当前无法形成可信输出；它们与业务指标为零是不同状态。真实留存的覆盖判断另使用第21章的pending／incomplete／complete_accepted_prefix，不要把公开投影状态当作数仓覆盖证明。

小样本阈值是一项披露控制，不是法律匿名保证，也不是统计显著性。公开表中总量、分项、分母和相邻版本都可能被相减推断，所以要整组控制和固定延迟发布。内部精确daily与公开投影分别承担运维/对账和公开展示职责。

## 练习与答案

用一个句子区分“表分区”和“Kafka分区”：前者通常按日期等字段组织表数据以裁剪扫描，后者是有序消息日志与消费并行的单位。二者都叫partition，但重分区、顺序与位点语义不同。

用一个句子区分“备份”和“副本”：副本主要帮助当前服务在节点失败后继续读取；备份保留某时点状态帮助恢复误删或历史问题。同步复制可能同时传播误删，不能替代独立备份。
