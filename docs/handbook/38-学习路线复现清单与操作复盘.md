# 38 学习路线、复现清单与操作复盘

## 第一轮不要同时学习全部组件

先沿一条能手算的数据链完成闭环，再替换计算或存储组件。你有每周25–35小时，可把约一半用于项目操作，四分之一用于SQL/Java，余下用于原理复盘和面试讲解。时长是学习安排，不保证所有问题按周解决；遇到数据正确性问题先修复再扩展。

```mermaid
flowchart LR
  A[能解释业务与指标] --> B[能独立跑小样本]
  B --> C[能读懂去重和事务]
  C --> D[能复现离线与实时]
  D --> E[能制造并解释故障]
  E --> F[能给证据回答追问]
```

## 第一周：不启动VM也能完成

阅读01–08章，运行固定种子小样本，手算PV/UV/成功率，完成32章SQLite练习。画出所有ID和三种运行模式。阅读同意生命周期测试，解释拒绝后哪些访问事件停、哪些独立质量日志仍可能运行。产出一页指标定义和一份自己的手算结果。

第二阶段读09–13章，理解线上轻量部署与本机VM边界。在已有环境运行只读status，核对当前资源预算，学会正常停机和查IP。复制命令前先口述运行位置、输入、输出和预期副作用。不要一上来下载第二套大型镜像或建立重复VM。

## 第一次动手：一次不需要VM的完整小样本闭环

前置条件：第11章已完成，当前电脑已有仓库及 `.venv`；这里只生成合成数据，不读正式配置，不开端口，不调用模型。若是新电脑，先按第11章准备依赖，不把下面路径当作所有电脑都存在。已有环境使用 **Windows PowerShell**，先运行：

```powershell
Set-Location -LiteralPath (git rev-parse --show-toplevel)
if (-not (Test-Path -LiteralPath '.venv/Scripts/python.exe')) { throw '先完成第11章Python环境' }
$lessonRun = 'runtime/learning/quickstart-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
if (Test-Path -LiteralPath $lessonRun) { throw '目录已存在，请换新实验名，保留旧结果' }
git rev-parse HEAD
& .\.venv\Scripts\python.exe -m snow_statistics.cli demo --seed 42 --users 2 --output $lessonRun
if ($LASTEXITCODE -ne 0) { throw '演示失败，停止后续读取并保留错误' }
Get-ChildItem -LiteralPath $lessonRun | Select-Object Name,Length
$lessonModel = Get-Content -LiteralPath (Join-Path $lessonRun 'model.json') -Raw | ConvertFrom-Json
$lessonModel.quality
$lessonModel.daily | Format-Table source,app,date,pv,uv,requests,successes
Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $lessonRun 'fixture.json')
```

预期目录内有 `fixture.json`（固定种子输入）与 `model.json`（Python正确性基准）。本例 `quality` 为 raw=28、valid=28、duplicates=0、quarantined=0；日结果有两应用 × 三日期，共6行。第一个合成标识按规则活动3天，第二个只活动1天，所以各应用每日UV依次为2、1、1，三天独立标识仍只有2个。**这是合成样例，不是网站真实访问量，也不是28个用户。** 成功数来自固定随机种子，先逐条找完成事件再验证，不把所有事件行都当请求。

接着在同一个PowerShell终端验证模型并重复计算：

```powershell
& .\.venv\Scripts\python.exe -m snow_statistics.cli model (Join-Path $lessonRun 'fixture.json') --output (Join-Path $lessonRun 'model-replayed.json')
if ($LASTEXITCODE -ne 0) { throw '重算失败' }
$firstHash = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $lessonRun 'model.json')).Hash
$replayedHash = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $lessonRun 'model-replayed.json')).Hash
if ($firstHash -ne $replayedHash) { throw '同一输入重算内容不同，先检查版本与输入' }
Write-Output '固定输入重算一致'
& .\.venv\Scripts\python.exe -m pytest -q tests/test_acceptance.py tests/test_behavior.py tests/test_real_behavior.py
```

预期哈希一致、测试退出码为0。CLI命令执行结束就已退出，**无需停止任何VM或服务**；三个JSON保留在刚生成的目录中，下次可以直接读取或重算。重算输出已经存在时，应换一个新输出文件名用于新的实验记录，不把历史失败输出覆盖成成功。

需要可视化时再按第23章单独启动本地Streamlit，选“Python 正确性基准”，输入上面目录中的 `model.json`。不选择未启动的Doris来验证这个小样本，也不因为旧归档缺失就创建真实epoch。学习完在启动Streamlit的终端按Ctrl+C，文件依旧保留。

常见失败：`ModuleNotFoundError` 先查第11章解释器和包路径；`fixture.json` 不存在先查CLI退出码与输出目录；结果为零先看自己读的是哪个源、哪一天和哪个字段；测试失败先保存测试名、SHA及输入哈希。不要改正式采集开关来修本地练习。

面试追问：两次哈希一致能否证明分布式 exactly-once？答案：不能，它证明当前Python基准的固定输入结果可重现；网络重放、引擎Checkpoint、外部事务和真实数据缺口仍需各自实验。

## 从零搭建与每天操作采用不同路线

| 场景 | 按顺序做什么 | 完成后应拿到什么 |
|---|---|---|
| 新电脑从零学习 | 第11章工具与依赖 → 本章小样本 → 第32章SQL → 第12章单独建VM | 工具路径、源码SHA、小样本哈希和测试结果；不是直接上线 |
| 已有电脑当天学习 | 本章小样本或第36章只读检查 → 只选择本次要用的组件 | 本次输入、实际命令和结果；不重装整套环境 |
| 已有真实窗口的日常操作 | 第13章身份/位点/有效期 → 第24章真实恢复条件 → 第30章计算与发布 → 正常停止 | 当前窗口的新回执、真实cutoff与收尾记录 |
| 长时间关机后恢复 | 第13章缺口与新起点 → 第30章已登记副本到期清理 → 确认新窗口范围后再处理 | 明确缺失范围；不能默认把旧Checkpoint恢复成连续历史 |
| 只保留基础统计 | 第30章精简流程 → 线上公开接口与两个产品回归 | VM关闭时轻量统计仍可用；不自动删除历史 |

真实闭日路线包含等待业务日期结束及核验覆盖。时钟跨过午夜并不自动弥补停机期间超过7天保留期的明细；已有今天的新事件也不意味着昨天可以补齐。每一轮先读第00章当前状态，历史命令用于解释当时证据。

## 接下来三周：离线与建模

沿14–23章完成消息、CDC、ODS和Spark分层。每周只挑一个核心模型深入：先SCD2，再工单轮次，再会话/留存/漏斗。用5到20条自编合成事件覆盖重复、跨天、分类变更和重开。先在Python基准得到确定答案，再对照Spark输出。

产出应包含输入文件hash、关键SQL、手算表、actual结果和差异解释。只保存截图不够重现；只保存源码也不证明实际运行过。每次新实验使用新run ID，失败目录保留，正确结果经门禁后发布。

## 中期：实时、调度与治理

阅读24–26章和33章，解释watermark、Checkpoint、Doris事务和业务去重的区别。复现一个小规模恢复场景，确认旧事件重放不增加事实。将离线任务接到Airflow，再观察任务失败如何影响发布。最后投递核心表级血缘，读回Marquez，手动画图和实际图逐条对应。

不要为了演示一次故障而破坏真实数据消费者。用独立synthetic lane和目录执行。单宿主资源受限时分阶段切换，不把“所有组件同时绿色”作为学习成就。

## 后期：性能、湖仓和退出

阅读27–30章，先理解已有证据，再决定是否重跑百万样本。选择一个正结果和一个负结果写复盘，明确为什么裁剪有收益、为什么加盐可能变慢。完成一次轻量模式演练，证明业务和公开基础统计不需要本机数仓。

Iceberg重点掌握快照、字段/分区演进和文件维护，不必为了面试装上更多湖仓组件。Kafka/ZooKeeper故障专题重点记录确认条件和恢复后读回，不追求更多节点数量。

## 每次操作填写这份复盘

```markdown
# 实验名称与日期
- 问题：我希望验证哪个具体判断？
- 环境：源码SHA、引擎版本、VM内存/CPU、输入来源与hash。
- 预测：我预计看到什么，为什么？
- 操作：命令、执行机器、run ID，哪些步骤会产生副作用？
- 结果：退出码、行数/指标、实际输出与证据路径。
- 差异：和预测哪里不同，排除了哪些原因？
- 边界：没有测什么，哪些结论不能推广？
- 收尾：进程/VM是否正常停止，资源是否保留且归属明确？
- 下一步：一个最小且可验证的改动。
```

## 自测评分标准

“看懂”是能跟着文章解释；“会用”是离开文章能独立完成；“掌握”是改变输入或出现故障后仍能解释并恢复。给每章标0/1/2：0未读，1可照做，2可独立复现并回答追问。面试优先讲自己达到2的模块，不用全技术栈平均用力。

把下面清单复制进自己的学习笔记，完成后填写日期和证据路径；不要因为读过标题就勾选“会操作”。

- [ ] 能用第03章七条记录分别算出两应用的日指标，并解释接收行数、有效行数和请求量不同。
- [ ] 能按第06章运行WAL样例，指出重复接收、事务聚合、备份读回各验证了什么。
- [ ] 能按本章独立生成28条合成输入、重算得到同一哈希，并找到自己的输出目录。
- [ ] 能在第32章解释ROW_NUMBER与GROUP BY的区别，手算Join放大和次日留存。
- [ ] 能根据第21章区分pending、incomplete与有效分母，拒绝把缺口写成0%。
- [ ] 能在第23章选择正确看板源，解释Python、Spark归档、Doris和真实私有汇总的差别。
- [ ] 能按第12／24／30章解释本次启停及恢复范围，知道关闭与删除是不同操作。
- [ ] 能用第35章讲解稿给出一项实际证据及其资源、数据来源和未验证边界。

练习：如果今天只有90分钟，如何安排？答案示例：20分钟复习一个指标口径，30分钟跑一个五行SQL变体，20分钟解释一次边界情况，20分钟写复盘。不要用90分钟重启全套服务却没有一个明确问题。

## 最终检查

你应能在没有VM时展示架构、合成模型和历史验收包；能在有资源时复现一条完整离线链；能说明线上真实接入当前版本及未完成项；能随时将系统精简为基础统计。求职项目的价值来自可解释和可维护，而不只是一张组件很多的架构图。
