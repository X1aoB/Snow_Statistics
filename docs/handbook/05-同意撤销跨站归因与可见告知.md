# 05 同意、撤销、跨站归因与可见告知

## 用户会看到什么

两个产品开启统计配置后，会出现非阻断的访问统计说明，允许和暂不允许都可以直接操作，永久设置入口可再次打开。个人站通知根据html.lang切换中英文。小屏幕上正文可以滚动，允许/拒绝按钮保持可见；提示不是进入聊天的强制同意门槛。

说明中将两类处理分开：访问、角色选择和请求关联需要主动同意；脱敏生成完成日志的服务质量处理独立告知，不依赖访问统计同意。拒绝不应让聊天不可用，更不能把“知道了，继续”这种原有体验按钮当作统计同意。

### 正式新版小吉的设置位置（65fa0d0）

9月19日18:11香港正式晋级后，持久入口放在 **设置 → 隐私 → 访问统计设置**，右侧栏底部不再放统计按钮。打开后可以允许，也可以关闭；关闭说明不会等于允许统计。首次提醒仍是非阻断提示，不要求用户先找到设置才能拒绝。

正式说明为：“记录页面访问、角色选择和请求编号，帮助改进体验。不收集聊天内容或密钥。”同时说明“可随时在‘设置 → 隐私’中关闭；拒绝不影响聊天。”服务质量另行告知：“另行统计已记录生成请求的结果和耗时，不含聊天内容，不受此开关影响。”详细期限仍在“查看隐私说明”中，短文案不改变原数据处理范围。

实际操作：打开设置，选择隐私，点击“访问统计设置”；根据自己的意愿允许或关闭。只点“收起说明”或设置窗口的 ×，不表示允许。再次打开同一设置可以查看当前状态。通过键盘在统计面板允许/关闭后，焦点回到入口；关闭外层设置再打开时仍能打开统计面板。其他标签页撤销时同步关闭采集，但不会从当前输入或其他设置标签抢焦点。

这些分支先在候选 Chrome 中验证；18:12:34香港新版正式页面又通过实际 HTTPS/CSP 的首次提示、拒绝、允许、跨标签撤销与移动/桌面检查。该轮统计传输被本地合成503拦截，没有制造正式采集数据，也没有模型调用。当前可按这个正式路径操作，不能把旧侧栏位置继续当作现行入口。

```text
配置off → 不安装采集能力
配置on、未选择 → 提示可见，无访问事件和匿名ID
主动允许 → 保存30天截止偏好 → 采集后续事件
拒绝/撤销/到期/GPC/DNT → 清队列、Abort在途、清统计ID、移除请求hook
```

## 当前实现的关键位置

`analytics.mjs`每次track和flush前重新检查持久同意期限与浏览器隐私信号；还设置到期计时器，因此长时间打开而没有点击的页面也会停止。监听storage事件，使同一来源另一标签页撤销后立即生效。检查发生在真正发送之前，不能只在页面加载时判断一次。

命名空间为 `snow.statistics.v1.<app>.`。anonymous和session是统计辅助标识；consent保存允许截止时间，拒绝偏好用负截止时间表示。负值是“不再反复询问”的偏好，不是匿名ID。撤销不删除主题、语言、IndexedDB聊天或签名数据。

已经送达并确认的事件不能靠Abort倒流删除；告知应说“停止后续采集”，历史按既定保留规则处理。不同来源的浏览器存储不能互相直接清除；在个人站撤销不自动替小吉修改自己的选择。

## 一次性入口的处理

个人站只对目标为 `https://snow.xiaob.dev` 且没有其他业务锚点的链接附加专用fragment。fragment避免进入目的服务器的普通请求URL。小吉没有有效同意时立即丢弃该专用片段，以后再允许也不追溯先前到达；已有业务hash不能删除。

注意：此实现限制的是用途和生命周期，不是不可伪造的身份系统。归因窗口仍由事件时间和离线模型校验。两个应用长期匿名ID独立，不跨设备拼接。

## 同意与下游确认是两个不同边界

截至9月19日18:31:57香港，先前已经获得确认的访问事件已在独立本机流程中完成HDFS双副本落地读回和原Kafka消费确认；writer随后保持暂停，全部实验VM关闭。这是已接收数据的受控处理进度，不会替任何浏览器打开同意开关，也不会恢复已经撤销的匿名标识。撤销负责停止后续访问采集，已经确认的数据仍按原保留期限处理，不因复制到数仓而延长期限。

这里的Kafka ACK不是服务质量日志的投递ACK。18:32香港校准时，质量链路还没有已确认样例；后续18:56:54香港，在用户完成真实对话并收到回复后，质量日志投递、请求去重和基础聚合的独立只读验收已通过。核验程序未调用模型制造样例，也没有读取聊天正文。这项通过不改变访问统计必须主动同意的规则；仍没有真实闭日报表可以展示。低内存56条golden全部为合成数据，不计入公开统计或用户人数。恢复与资源条件见[第24章](24-Flink水位线Checkpoint与迟到修正.md)。

## 自己测试

执行位置为Windows PowerShell，工作目录为Snow_Statistics仓库根目录；以下只运行合成适配器测试，不访问正式采集器。

```powershell
node --test adapters/browser/analytics.test.mjs adapters/browser/bootstrap.test.mjs
```

用本地合成候选开启两个同源标签页，先允许，再在A页撤销，确认B页不再有snowStatisticsRequest、统计anonymous/session消失。开开发者工具Network只筛选 `/analytics/`，不要在录制材料中展示真实用户请求或令牌。

练习：拒绝后localStorage还有一个负数consent，是否说明仍在跟踪？

答案：不能只凭存在一个统计偏好键判断。要检查是否创建匿名/会话ID、是否发送事件、是否注册请求hook以及该键的用途。当前负值仅记住拒绝期限；业务功能和独立质量日志另按各自边界处理。

## 常见失败与处理

| 看到的现象 | 先检查什么 | 正确处理 |
|---|---|---|
| 点允许后仍显示关闭 | 浏览器GPC/DNT隐私信号、是否禁止本地存储 | 这是保护性关闭；保留用户隐私设置，聊天继续可用。不要为了增加采集率绕过信号。 |
| 长时间开页后停止采集 | 原同意截止时间是否已经到期 | 重新展示当前选择；只有新的主动允许才能恢复后续采集，不能补报到期后的操作。 |
| A标签页关闭，B标签页仍有旧画面 | 两页是否为同一个Origin、B页当前版本是否正确 | 同源页应同步撤销；个人站和小吉是不同来源，需要分别关闭。用本地合成候选定位storage监听，不清空全部浏览器存储。 |
| 接口503、断网或超时 | Network中请求状态及有限重试是否结束 | 丢弃未确认的统计事件，业务继续；不要让聊天提交等待统计恢复，也不要把失败显示成零次访问。 |
| 关闭后仍存在consent键 | 键的值与用途，是否还有anonymous/session或新事件 | 记住拒绝选择可以保留，匿名与会话统计标识应清除；不要误删聊天IndexedDB或业务Cookie。 |
| 跳转后没有入口归因 | 两端是否均已允许、链接是否已有业务锚点、是否超时 | 缺少条件时不归因属于预期；不能在后来同意时补报旧入口，也不能删除业务锚点凑归因。 |

排查只在自己的浏览器或隔离合成候选进行。截图和录像遮住密钥、私人聊天及开发者工具中的敏感请求；技术演示不需要展示原始事件内容。

## 9月19日14:09–14:15历史真实采集与撤销验收

首次上线后，测试者在两站分别主动允许，实际访问、角色选择和入口跳转事件已被接收并聚合。两个应用没有共享匿名身份。一次观察到的入口标记在目的页面消费并清除；受控浏览器未暴露自动打开的新标签，因此当时用观察到的目的链接另开标签验证，不把它说成完整自动 target=_blank 流程通过。

两站分别撤销后，其他标签页状态同步关闭。继续导航、角色切换和输入仍可用，14:15:38香港的只读回验没有因这些撤销后操作新增采集。这里省略内部小计数、位点和标识；少量技术验收行为不能解释为自然用户规模或增长业绩。

这段是旧正式版本的真实传输证据；新版65fa0d0的18:12回归使用合成503隔离传输，两种证据分别说明自己的范围。质量日志在10:14:23 UTC这一历史时点仍无已确认样例，不能用当时的访问成功代替质量验收。后续10:56:54 UTC已有独立真实完成事件验收通过，见[第10章](10-两个产品接入与日志质量链路.md)；两类证据继续各自对应自己的范围。
