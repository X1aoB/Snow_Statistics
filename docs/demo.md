# 离线演示与面试讲解

项目已经可以在不启动虚拟机、不接入真实用户的条件下展示模型、契约和验收证据。真实引擎执行结果与 Python 正确性基准分别标注。完整对应关系见 [验收矩阵](completion-checklist.md)。

## 十分钟演示

1. 用 README 的三模式表说明边界：产品只持有可关闭的适配副本，公开页始终读取轻量汇总。轻量服务可以独立发布，VM/Kafka/Doris 关闭不会使业务等待统计。展示默认 off 配置和 [退出证据](evidence/retirement.json)。
2. `uv sync --frozen --extra dev --extra lab`，随后 `uv run snow-stats demo --users 100`；运行 `uv run streamlit run dashboard/app.py --server.address 127.0.0.1`。选择“Python 正确性基准”，解释固定时钟、固定种子、真实与合成隔离。它不需要原项目或服务端凭据。
3. 展示 SCD2、渠道点击归因与工单重开：发生时分类与当前分类是不同问题；最后有效点击窗口 30 分钟、每次点击最多一次转化；工单轮次与每日状态快照解决不同粒度的问题。用 [模型手册](behavior-models.md)的手算样例核对，不用数据库行数推断业务人数。
4. 如本机有保留归档，选择“Spark 已发布运营与行为模型”及“Marquez 血缘归档”；没有 runtime 归档的新克隆使用仓库中的公开 evidence。明确指出归档日期与数据截止时间。展示 [百万条 YARN](evidence/scale-1m.json)、[10 万条实时对账](evidence/realtime-scale100k.json)和 [小样本新鲜度](evidence/freshness.json)。
5. 用 [优化报告](optimization.md)解释物理计划、任务读入字节和三轮中位数，再用 [Kafka/ZooKeeper](ha.md)和 [Iceberg](lake.md)展示失败、恢复和负结果。最后展示精简后公开 API 不变及适配器可反向移除的验收。

演示页面读取本机文件或专用私有服务，不应为了面试临时开启生产采集、发布私有数据库，或同时打开所有大数据组件。需要现场重跑引擎时，按对应手册选择一个 profile 并先过动态资源检查。

## 可以据实写进简历的内容

> 独立设计并实现可移除的用户行为分析与数据仓库实验：以 Python/SQLite 支撑基础统计，通过 Kafka、Spark/Hive/YARN、Flink、Doris 实现离线及实时分层；构建 SCD2、留存/归因和工单快照，使用 Airflow 和 OpenLineage/Marquez 管理核心任务与表级血缘。
>
> 在本机 VMware 受限资源环境下完成百万条合成事件离线验收、10 万条实时/轻量/离线整数指标对账与 Checkpoint 恢复；保留物理计划、任务指标和故障读回证据，验证基础统计可脱离完整数仓继续运行。

面试中的数字必须连同条件说明：百万条 YARN 的应用时长为 115.023 秒，2/2/1 GiB VM、单远端 executor；10 万条实时是按事件时间排序的历史回放；P95 12.016 秒来自 300 条本地 HTTP 样本，包含查询/轮询开销，不是生产公网长期 SLA。不会把合成数据称作真实用户业务量。

## 值得讲清楚的取舍

| 问题 | 可验证的回答与入口 |
|---|---|
| 为什么还保留 SQLite？ | 业务低流量、维护成本低；持久化确认、聚合位点和更新事务、磁盘满拒收均有测试。完整数仓不负责公开页可用性。 |
| exactly-once 怎么证明？ | 分开谈接收 ID 去重、同步至少一次、Flink 状态恢复、Doris 2PC 和业务主键。本项目没有从 Checkpoint 成功推导所有外部副作用恰好一次。见 realtime.md。 |
| 为什么优化有失败结论？ | 单核小样本热点加盐增加了读取与 shuffle，中位数更慢。解释计划和资源证据，比展示一个无条件加速比更可信。 |
| Iceberg 文件重写一定更少吗？ | 本次从月分区演进至日分区，重写 2 文件产生 8 文件，数量增加；时间旅行和数据一致性通过。见 lake.md。 |
| 任务有输出就算完成吗？ | kill 后可能只有 START 和部分副作用。只声明验证过的终态；未知尝试保持未结束，需要权威状态或新尝试。见 lineage.md。 |
| 虚拟机三节点算容灾吗？ | 能研究复制、选主、会话与恢复；同一物理宿主仍是共同故障边界。 |

## 后续学习安排

每周继续保留 SQL 窗口/去重/留存与执行计划练习，Java 状态机/序列化/并发练习，以及一次失败复盘。按需求择一拓展多分区顺序、真实长期容量、HDFS fencing/自动 HA 或实际列级血缘，先定义新的验收条件再加组件；当前证据不自动覆盖这些范围。
