# 首次真实事件闭环验收（2026-09-19）

本页记录已执行的首次真实小样本接入，不公布原始事件、用户标识、私有消费位点或可推断用户数量的指标值。原始数据与完整元数据回执均在忽略的 `runtime/real/` 目录，由原接收时间约束保留期。

## 实际执行范围

- 独立线上轻量采集服务产生的事件，经受限 SSH 私有读取通路进入本地独立真实 epoch；没有向正式采集库注入合成事件。
- 统一入口完成可靠同步，Kafka 确认后推进本地同步位点。Flink 实时写入独立 Doris 数据库。
- 同一截止位点下，独立 Python 口径样例计算、实际 Doris 整数结果与线上 SQLite 单个只读事务的整数结果哈希相同。该对账不将日 UV 相加当作跨日期人数。
- 受控暂停保留最终外部 Checkpoint，停止全部真实引擎并软关闭 analysis 虚拟机。随后重新启动，使用相同 JAR、相同代际与原截止时间，以 `NO_CLAIM` 从精确 Checkpoint 恢复；新的实际 JobID 及 Flink REST 恢复路径均已读回。恢复后整数结果保持一致。
- 第二次受控暂停后，离线阶段将已经捕获的原始批次落入 HDFS。非空批次文件与不可变快照逐一校验内容哈希，实际块位置为两台已登记 DataNode，各有一份副本。
- 关闭离线服务后再启动真实存储阶段，读取实际 Kafka 集群与 Topic 代际，完成确认并独立读回已提交位点。它与已经验证的 HDFS 批次末端和当前 Broker 末端一致，本地 pending 标记消失，已提交状态与落地回执一致。
- 验收结束时真实 Flink 作业保持暂停，全部实验虚拟机软关闭；未因停止删除数据、卷或 Checkpoint。
